## 4. Criterio de Decisión

Las siguientes reglas se aplicaron (implícitamente durante Phase 5, explícitamente en este memo):

### Regla 1: Contenido funcional único = PRESERVED
Si la rama contiene código funcional (no docs, no `_ctx` artifacts) que NO está en main y NO fue mergeado por un PR alternativo, se PRESERVED.

### Regla 2: Reemplazo mergeado = DELETED
Si el contenido funcional de la rama ya fue mergeado a main vía un PR alternativo (ej: PR #84 reemplazó PR #83), la rama se DELETED.

### Regla 3: Redundancia con rama PRESERVED = DELETED
Si el contenido funcional de la rama overlap significativamente con una rama PRESERVED (ej: docs-skillhub vs batch-2d), la rama redundante se DELETED.

### Regla 4: Valor residual bajo = DELETED
Si la rama contenía principalmente documentación histórica, artefactos de contexto (`_ctx/`), o código que evolucionó independientemente, se DELETED.

### Regla 5: En caso de duda = PRESERVED (default)
Si no había evidencia suficiente para confirmar que el contenido era recuperable o redundante, la rama se PRESERVED. Este es el principio fail-safe.

**Nota**: Las reglas 2-4 se aplicaron a las ramas DELETED. La regla 5 habría protegido una rama si no se pudiera confirmar su redundancia, pero en los 3 casos DELETED existía evidencia razonable (aunque con incertidumbres documentadas).
